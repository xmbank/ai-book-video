# AI 图书带货视频生产系统

这是按《加入生财不到一年，我的视频号图书带货 23 天 5 万佣金的复盘》中展示的生产方法实现的本地 Web 工作台。它不是网页版剪映，也不是通用视频任务面板；首页是热点采集表，一条素材进入任务后，所有逐字稿、候选稿、音频、字幕、场景图、书籍信息和成片都归档在同一任务下，可查看、修改、保留版本和局部重跑。

当前本机已经用离线任务跑通八个阶段，并生成两种风格的 1080×1920 H.264/AAC 成片。新任务把“ASR 校对”和“吸引力二创”彻底分开，并在写稿前确认真实图书与商品卖点；真实抖音任务还需要在页面设置中配置 LLM、图片生成和火山 TTS 凭证。

## 文章对应流程

```text
热点采集表 / 粘贴抖音分享链接
  -> 1. ASR 校对：只修错字、断句、口误、博主痕迹和风险表达，不承担二创
  -> 2. 书籍与商品：确认真实书名、作者/版本、封面和可核实卖点
  -> 3. 三策略二创：先提炼内容卡，再按反常识、人群痛点、商品方案分别创作
  -> 4. 分段音频：长稿按约 24-28 秒切段，逐段 TTS 后合并
  -> 5. 竖屏视觉分镜：视觉导演拆镜，逐张生成原生 9:16 单图并自动质检
  -> 6. 成片风格与数量：选择多种视觉风格及每种生成数量
  -> 7. 批量成片：HyperFrames 合成字幕、书名/作者和健康声明
  -> 8. 日志 / 人工确认：查看文案、商品资料、场景图和输出验收结果
```

镜头数默认按最终 TTS 音频自动计算：强转化风格约每 3.6 秒一镜，其他风格约每 4.5 秒一镜，范围为 6–63 张；也可以手动指定。健康内容的场景提示词使用人物状态、饮食、活动、睡眠和生活选择表达，避免器官、病床、手术、药物等医疗病理画面。

真实链路的提示词已升级为 v3。ASR 校对稿允许与逐字稿接近，因为它只负责准确；二创阶段会先提炼单一核心观点、目标人群、可用事实、待核实论断、商品理由和需避开的源文短语，再生成三种结构明显不同的候选稿。每个候选都会计算开头吸引力、原创度、商品具体性、目标时长和安全性，系统默认采用综合分最高的一稿。每次实际发送的 System/User 提示词、版本和来源仍随任务产物保存，便于复核。

图片链路不再让模型生成横版九宫格，也不再把横格强裁成竖图。默认主视觉为 `book-sales`（强转化图书）：视觉导演按开场冲突、目标人群痛点、可信来源、方法演示、理想状态、商品揭示和行动收口组织镜头，并要求前 8 秒出现商品，其后持续重复商品记忆。模型逐张生成原生竖图，统一归一化为 720×1280；系统检查尺寸、空白图、近重复、商业对比度、色彩能量、商品曝光、人脸/人物动作和连续静物镜头，低质量图片会自动重生一次。九张一组的联系表只用于页面总览，不参与成片。

正式带货默认不再要求用户外出寻找封面。系统会严格从来源内容中提取 2–3 条商品卖点，并调用已配置的图片模型生成无文字概念封面视觉，再由本地程序准确叠加书名和作者，避免图片模型写错字。页面仍支持上传 JPG、PNG 或 WebP 手动替换自动封面。成片商品镜头会后期叠加当前封面、准确书名和最多 3 条来源卖点；只有连书名或两条来源卖点都无法识别时才会请求人工补充。

## 页面能力

- ASR 校对：原始逐字稿和校对稿对照编辑；页面明确提示本步相似度高是正常现象。
- 书籍与商品：查看自动识别的书名、作者/版本和来源卖点，预览或重新生成 AI 概念封面，也可手动替换图片，并设置二创强度和目标口播时长。
- 三策略二创：查看内容卡、三种策略、系统推荐和文案质量评分，选择后仍可继续修改。
- 配音：查看分段计划、试听合并音频和分段产物。
- 竖屏视觉分镜：查看原生竖图、确定性联系表、镜头职责、视觉目的、商品曝光方案、商业视觉质检和自动重生结果。
- 风格：五种预设分别设置输出数量，单种最多 5 条；切换主视觉风格会使场景图待重跑。
- 成片：预览、下载每种风格的 MP4，并保留历史版本。
- 复核：查看商品资料、文案评分、场景图质检、合规和媒体规格检查结果。

内置风格为 `book-sales`、`clean-narration`、`typewriter-dark`、`dark-knowledge` 和 `book-broadcast`，真实任务默认使用 `book-sales`。

## 真实链路配置

先复制配置文件并在页面“设置”或 `.env` 中填写真实参数：

```bash
cp .env.example .env
uv run book-video doctor
```

必须配置：

- `LLM_API_KEY`、`LLM_MODEL`、`LLM_BASE_URL`：OpenAI-compatible Chat Completions，用于 ASR 校对、内容卡、三策略二创、书籍识别和视觉导演。
- `IMAGE_API_KEY`、`IMAGE_MODEL`、`IMAGE_BASE_URL`、`IMAGE_SIZE`：OpenAI-compatible Images Generations，用于逐张生成原生 9:16 场景图；默认请求尺寸为 `1024x1536`。
- `VOLC_TTS_API_KEY`、`VOLC_TTS_RESOURCE_ID`、`VOLC_TTS_VOICE_TYPE`：豆包语音合成模型 2.0。`API Key` 在新版豆包语音控制台的“API Key 管理”中获取；资源 ID 默认为 `seed-tts-2.0`。

配置后，网页中粘贴有效抖音分享链接即可创建真实任务。系统会先完成采集、校对和书籍识别，随后自动提取来源卖点并生成 AI 概念封面，不需要提前准备图片。命令行等价入口：

部分抖音分享页会只返回“请在抖音内观看”的空壳页面。工作台会自动调用带签名的作品详情接口：优先使用 `.env` 中的 `DOUYIN_COOKIE`，未填写时读取本机 Chrome 的抖音会话。因此这类链接需要先在 Chrome 登录抖音；Cookie 只在进程内使用，不会写入任务产物或日志。

```bash
uv run book-video run \
  --share "抖音完整分享文案或链接" \
  --keyword "健康图书" \
  --scene-count 0
```

`--scene-count 0` 表示按最终音频时长自动计算；也可以手动填写 6–63。`--book-cover` 和可重复的 `--selling-point` 仍可用于覆盖自动结果，但不再是必填项。

首次真实验收需要一条实际图书视频链接和可用的三类 Provider 凭证。抖音页面结构、账号权限和图片模型支持的尺寸可能变化，失败会记录在对应阶段并允许从该阶段重跑。

## 任务持久化

```text
data/tasks/{task-id}/
├── task.json                  # 任务配置与活动版本指针
├── pipeline-state.json        # 八阶段状态、错误和产物
├── artifacts.json             # 文件大小、SHA-256 和所属阶段
├── source/                    # 抖音元数据与原视频
├── transcript/                # 原始稿与修复稿版本
├── scripts/                   # 内容卡、三策略候选、质量分和最终稿版本
├── tts/                       # 分段音频、合并音频和计划
├── subtitles/                 # JSON/SRT 字幕版本
├── scene-images/              # 原生竖图、预览联系表、视觉分镜和质检清单
├── book/                      # 书名/作者/版本、卖点、封面与人工确认版本
├── styles/                    # 风格和每种输出数量
├── output-plans/              # 每种风格的分镜与渲染清单
├── render-project-*/          # HyperFrames 工程
├── renders/                   # MP4 和 ffprobe 验收报告
└── review/                    # 最终人工复核报告
```

旧版本不会被覆盖。编辑逐字稿、最终稿、书籍信息、字幕或风格后，系统只把受影响的下游阶段标为待重跑。

## 开发验收

```bash
uv run python -m compileall -q src tests
uv run pytest -q
npm run build
```

后端测试覆盖商品资料门禁、候选卖点、强转化分镜、商业图片质检与重生、封面上传、风格失效、商品英雄卡和公共错误提示；前端生产构建也纳入开发验收。离线成片规格为 H.264/AAC、1080×1920、30fps。

当前不包含自动登录抖音浏览榜单、自动发布到视频号/抖音、佣金归因和多人权限。第一版的热点判断仍由人完成，系统负责把选中的链接变成可追溯、可批量重跑的成片任务。
